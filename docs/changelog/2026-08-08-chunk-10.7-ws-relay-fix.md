# Chunk 10.7 — WS relay fix (2026-08-08)

**Problem:** Bot was configured to connect to `wss://pm-bot-relay.fly.dev/`
but `connected: false`, `n_frames: 0`, `last_ws_error: null`. The
`open` event never fired. The Stage panel stuck on "Connecting…".

**Root cause:** `openKalshiWs` always called
`new WebSocket(url, { headers } as unknown as string[])` — passing
`{ headers }` as the second arg. CF Workers treats that second arg
as a protocols string (it should be `string[] | string`), so the
`{ headers }` was silently dropped. Result: the WS upgrade went
out without auth headers, the relay accepted the connection, but
the protocol negotiation was wrong and `open` never fired.

**Fix:** Detect the relay (or any non-Kalshi host) by checking
`!url.includes("kalshi")` and use the plain
`new WebSocket(url)` form — no second arg. The relay handles
Kalshi auth server-side; the Worker just needs a clean WS upgrade.

**Also added:** 10-second `open` event timeout. If `open` doesn't
fire within 10s, the bot logs `_lastWsError = { code: "open_timeout", ... }`,
closes the WS, and schedules a reconnect. Catches the silent-CLOSING
case so the dashboard never sits on "Connecting…" forever.
