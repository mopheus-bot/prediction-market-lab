### Monthly limits card (new section in the dashboard)

Driven by the extended `/api/pm/cost` endpoint. Two sections:

**Cloudflare Workers Paid** — 4 progress bars (green/amber/red at 90%/70%):
- **Workers requests** (extrapolated from 7d): current / 10M limit
- **Workers CPU time** (extrapolated from 7d): current / 30M ms
- **D1 writes (24h)**: current / 100K limit
- **R2 storage**: current / 10GB

Plus a "resets in N days · on YYYY-MM-DD · day N/30 of cycle" line at the top.

**Fly.io relay** — 1 progress bar:
- **Shared-cpu-1x (1GB RAM)** plan: $used / $1.94 per month

Plus a status line (🟢 running / 🟡 stopped / ❔ unknown / ⚪ not deployed / ⚪ no API token) + free-credit-remaining indicator.

### CF billing cycle (hard-coded)

User signed up for CF Workers Paid "a few hours ago" on 2026-08-08. CF bills monthly on the signup date, so the env var `CF_BILLING_CYCLE_START=2026-08-08` is set in `wrangler.jsonc`. The cost endpoint computes "resets in 29 days · on 2026-09-07" from this.

### Fly.io integration

- `FLY_API_TOKEN` (the `FlyV1 fm2_...` machine token) is set as a Worker secret.
- `FLY_APP_NAME=pm-bot-relay` and `FLY_FREE_CREDIT_USD=0.83` are set as wrangler vars.
- The cost endpoint calls `GET https://api.fly.io/v1/apps/{name}/machines` and computes hours-this-month × per-hour rate.
- Currently the relay is `not_deployed` (app doesn't exist on Fly.io yet). When it's deployed, the cost section will show real numbers automatically.

Added `cpuTime` to the `workersInvocationsAdaptive.sum` GraphQL query in `src/api/cf-analytics.ts`. The `cf_monthly.cpu_ms` progress bar pulls this and extrapolates to the 30-day window.

    plan: "shared-cpu-1x-1gb",

Dashboard shows: "resets in 29 days · on 2026-09-07 · day 1/30 of cycle" + 4 green bars at 0% + 1 Fly.io bar at 0% with "⚪ status: not deployed · free credit remaining: $0.83".

### Edge cases handled

- **Today == cycle_start** → days_elapsed = 1 (not 0). Without this, the bar would be 0% even on the first day.
- **Past cycle end** → days_until_reset = 0 (not negative). The bar still renders.
- **No `FLY_API_TOKEN`** → status: "no_token", cost: 0, free_credit_remaining: $0.83. No error.
- **App not found on Fly.io** → status: "not_deployed", cost: 0. No error.
- **CF Analytics fails** → `notes` field explains. Cost falls back to 0. No error.

### What's still manual

- The relay isn't deployed yet. When you deploy it (`fly launch --name pm-bot-relay --vm-size shared-cpu-1x --memory 1024`), the dashboard will automatically show machine hours × rate.
- The CF billing date is hard-coded. If you switch plans or the cycle date changes, update `wrangler.jsonc`'s `CF_BILLING_CYCLE_START` and redeploy.
- The 7d → 30d extrapolation is approximate. If you want exact monthly numbers, we'd need a CF Analytics query that spans 30 days (currently the API caps at 7d per query, so we'd need 4 sequential queries).
